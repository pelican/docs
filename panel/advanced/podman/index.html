Deploying with Podman

Run the Pelican Panel's Docker image with rootless Podman on Fedora, RHEL or Alma/Rocky Linux, using a Quadlet so systemd manages the container.

This guide runs the panel's Docker image with rootless Podman on Fedora, RHEL, or Alma/Rocky Linux, using a Quadlet so systemd manages the container. Like the Docker guide, it uses SQLite and serves the panel over plain HTTP on port 80.

Prerequisites

  • OS: Fedora, RHEL 9+, or Alma/Rocky Linux 9+ with SELinux enforcing.
  • Packages: podman 5 or newer (sudo dnf install podman).
  • A regular (non-root) user to run the panel. The commands below use your-user; replace it with that user's name.

Data is stored in Podman named volumes (pelican-data and pelican-logs), under ~/.local/share/containers/storage/volumes. Podman applies the correct SELinux labels to these automatically.

Optional Configuration

HTTPS and Reverse Proxies

The image supports the same BEHIND_PROXY, LE_EMAIL and TRUSTED_PROXIES environment variables as the Docker deployment. Add them under env: in pelican.yaml. If the panel serves HTTPS itself, also publish port 443 (containerPort: 443, hostPort: 443).
