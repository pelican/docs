# Additional Configuration

<Admonition type="danger">
These are advanced configurations for Wings. You risk breaking Wings and making containers unusable if
you misconfigure something. Proceed only if you know what each configuration value does.
</Admonition>

You must apply all changes to your Wings `config.yml` file located at `/etc/pelican` and restart wings.  
Verify your config file using [Yaml Lint](http://www.yamllint.com/) should you receive errors related to YAML parsing.

## Managed by the Panel

Some values are managed by the Panel and appear in the Configuration File tab of the Node.
Most of them are sent to Wings whenever you save a Node, so if you change one of those by hand in `config.yml`, the Panel overwrites it on the next save. Set them in the Panel instead.

The values marked ✗ in the **Sent on save** column are the exception. Wings doesn't accept them from Panel updates or from the auto deploy command, so changing them in the Panel doesn't change them on the node. Update them in `config.yml` by hand, and keep the Panel setting in sync so the two agree.

| Setting Key                   | Where to set it in the Panel                                                         | Sent on save |
| ----------------------------- | ------------------------------------------------------------------------------------ | :----------: |
| `uuid`, `token_id`, `token`   | Generated by the Panel (Configuration File tab)                                      |      ✓       |
| `api.port`                    | Basic Settings → Port / Listen Port                                                  |      ✓       |
| `api.ssl.enabled`             | Basic Settings → SSL                                                                 |      ✓       |
| `api.ssl.cert`, `api.ssl.key` | Extra Configuration → SSL Certificate (defaults to the Let's Encrypt paths for the node FQDN) |      ✓       |
| `api.upload_limit`            | Advanced Settings → Upload Limit                                                     |      ✓       |
| `system.sftp.bind_port`       | Advanced Settings → SFTP Port                                                        |      ✓       |
| `system.data`                 | Advanced Settings → Daemon Base Directory                                            |      ✗       |
| `allowed_mounts`              | Mounts (see the note below)                                                          |      ✗       |
| `remote`                      | The Panel URL (`APP_URL`). The auto deploy command sets it with `--panel-url`        |      ✗       |

The collapsed **Extra Configuration** section at the bottom of the Advanced Settings tab on the Edit Node page can also set the options marked with ✓ in the **Panel** column of the tables below.
A field left empty in the Panel is not sent, and Wings keeps its own value. Clearing a field in the Panel does **not** reset a value Wings already applied. To reset it, edit `config.yml` by hand.

Options marked with ✗ can only be changed by editing `config.yml` on the node.

<Admonition type="info">
Wings doesn't accept `allowed_mounts` from the Panel's config updates, so extra mount paths must be added to `config.yml` by hand. The list in the Configuration File tab only includes the Mounts assigned to the node.
</Admonition>

<Admonition type="info">
Custom SSL certificate paths are applied when you save the Node. Wings ignores Let's Encrypt paths sent by the Panel and keeps the paths it already has, so clearing a custom path in the Panel won't switch Wings back. Edit `api.ssl.cert` and `api.ssl.key` in `config.yml` to do that.
</Admonition>

<Admonition type="info">
Wings applies Panel updates by merging them into its current configuration. Options that Wings reads under a different name from the Panel's JSON payload can't be set from the Panel, which is why some options are `config.yml` only.
If you want Wings to ignore everything the Panel sends, set `ignore_panel_config_updates: true`.
</Admonition>

## Custom Network Interfaces

You can change the network interface that Wings uses for all containers by editing the network name; it is by default set to `pelican_nw`. For example, to enable Docker host mode change the network name to `host`.

<Admonition type="warning">
  Changing network mode to `host` grants Pelican direct access to all machine interfaces and Panel users can bind to any IP or Port even if it's not allocated to their container. You will lose all benefits of Docker network isolation. It is not recommended for public installations that are hosting other users' servers.
</Admonition>

### Example of usage

```yml
docker:
  network:
    name: host
    network_mode: host
```

After making changes, the following commands will stop the Wings, remove the Pelican network, and start the Wings again. Run at your own risk.
`systemctl stop wings && docker network rm pelican_nw && systemctl start wings`

### All Docker Network Keys

All of these keys live under `docker.network`.

<Admonition type="warning">
Containers use `network_mode`, which can only be set in `config.yml`. If you change `name` (in the Panel or in `config.yml`), set `network_mode` to the same value, then remove the old network and restart Wings as shown above. Otherwise containers keep using the old network mode.
</Admonition>

| Setting Key           |     Default Value      | Panel | Notes                                                                              |
| :-------------------- | :--------------------: | :---: | ---------------------------------------------------------------------------------- |
| name                  |      `pelican_nw`      |   ✓   | Name of the Docker network. It is created if it doesn't exist                      |
| network_mode          |      `pelican_nw`      |   ✗   | Docker network mode for containers, e.g. `host`                                    |
| driver                |        `bridge`        |   ✓   | Docker network driver                                                              |
| interface             |      `172.18.0.1`      |   ✓   | Interface used to create the network. Must not conflict with other Docker networks |
| dns                   |  `1.1.1.1`, `1.0.0.1`  |   ✓   | DNS servers used by containers                                                     |
| ispn                  |        `false`         |   ✓   | Use the ISPN network option                                                        |
| IPv6                  |         `true`         |   ✓   | Enable IPv6 on the network                                                         |
| is_internal           |        `false`         |   ✗   | Create the network as internal, with no outbound access                            |
| enable_icc            |         `true`         |   ✗   | Allow inter-container communication on the network                                 |
| network_mtu           |         `1500`         |   ✗   | MTU of the network                                                                 |
| interfaces.v4.subnet  |    `172.18.0.0/16`     |   ✓   | IPv4 subnet of the network                                                         |
| interfaces.v4.gateway |      `172.18.0.1`      |   ✓   | IPv4 gateway of the network                                                        |
| interfaces.v6.subnet  | `fdba:17c8:6c94::/64`  |   ✓   | IPv6 subnet of the network                                                         |
| interfaces.v6.gateway | `fdba:17c8:6c94::1011` |   ✓   | IPv6 gateway of the network                                                        |

```yml
docker:
  network:
    interface: 172.18.0.1
    dns:
      - 1.1.1.1
      - 1.0.0.1
    name: pelican_nw
    ispn: false
    IPv6: true
    driver: bridge
    network_mode: pelican_nw
    is_internal: false
    enable_icc: true
    network_mtu: 1500
    interfaces:
      v4:
        subnet: 172.18.0.0/16
        gateway: 172.18.0.1
      v6:
        subnet: fdba:17c8:6c94::/64
        gateway: fdba:17c8:6c94::1011
```

## Enabling Cloudflare proxy

Cloudflare proxying of the Wings isn't beneficial since users will be connecting to the machine directly and bypassing any Cloudflare protection. As such, your Node machine IP will still be exposed.

To enable Cloudflare proxy, you must change the Wings port to one of the Cloudflare HTTPS ports with caching enabled (more info [here](https://developers.cloudflare.com/fundamentals/get-started/reference/network-ports/)), such as 8443, because Cloudflare only supports HTTP on port 8080. Select your Node in the Admin Panel, and on the settings tab, change the port. Make sure that you set "Not Behind Proxy" when using Full SSL settings in Cloudflare. Then on Cloudflare dashboard, your FQDN must have an orange cloud enabled beside it.

You are unable to proxy the SFTP port through Cloudflare unless you have their enterprise plan. Server transfers will most likely not work either due to [Cloudflare's request body limits](https://developers.cloudflare.com/workers/platform/limits/#request-limits).

## Container PID Limit

You can change the total number of processes that can be active in a container at any given moment by changing the `container_pid_limit` value. The default value is `512`, and it can also be set in the Panel.
You can set it to `0` to disable the limit completely. However, this is _not_ recommended as the limit prevents malicious overloading of the node.
Restart wings and your game server to apply the new limit.

### Example of usage

```yml
docker:
  ...
  container_pid_limit: 512
  ...
```

| :-------------------------- | :-----------: | :---: | --------------------------------------------------------------------------------------------------------------------------------------------- |
| domainname                  |     empty     |   ✓   | Docker domain name for all containers                                                                                                         |
| tmpfs_size                  |      100      |   ✓   | Size of the `/tmp` directory in MiB mounted into containers. Docker uses host memory for this, and it isn't counted against the server       |
| userns_mode                 |     empty     |   ✓   | User namespace mode for containers when Docker user namespace remapping is enabled. Set to `host` to disable remapping for Pelican containers |
| system_ips                  |      []       |   ✓   | IP addresses that users are allowed to bind to                                                                                                |
| use_performant_inspect      |     true      |   ✓   | Use a faster container inspect call                                                                                                           |
| overhead.override           |     false     |   ✓   | Use the values below instead of the built-in memory overhead tiers                                                                            |
| overhead.default_multiplier |     1.05      |   ✓   | Memory multiplier given to containers when overriding, so software such as the JVM stays below its limit                                      |
| overhead.multipliers        |     empty     |   ✗   | Map of memory size (MiB) to multiplier, used instead of `default_multiplier` for servers at or below that size                                |

| log_config.config           |   see below   |   ✗   | Options passed to the log driver                                                                                                              |

When `overhead.override` is `false`, Wings gives servers with 2048 MiB of memory or less 15% extra, servers with 4096 MiB or less 10% extra, and all other servers 5% extra.

```yml
docker:
  domainname: ""
  tmpfs_size: 100
  userns_mode: ""
  system_ips: []
  use_performant_inspect: true
  overhead:
    override: false
    default_multiplier: 1.05
    multipliers:
      2048: 1.15
      4096: 1.10
  log_config:
    type: local
    config:
      compress: "false"
      max-file: "1"
      max-size: 5m
      mode: non-blocking
```

## Running on Podman

Wings can use rootful Podman in place of Docker through Podman's Docker-compatible API. Wings runs as root, so it uses the system Podman socket. These steps assume a Fedora, RHEL, or Alma/Rocky Linux host with SELinux enforcing.

1. Install Podman's Docker compatibility package and enable the socket. This makes `/var/run/docker.sock` point at Podman, so skip the Docker install step.

    ```sh
    sudo dnf install podman podman-docker policycoreutils-python-utils
    sudo systemctl enable --now podman.socket
    ```

2. Install and configure Wings as described in [Installing Wings](/docs/wings/install), but in `wings.service` replace the three lines that reference `docker.service` with the following, otherwise systemd refuses to start it (`Unit docker.service not found`):

    ```ini title="/etc/systemd/system/wings.service"
    After=podman.socket
    Requires=podman.socket
    ```

3. Podman doesn't support Docker's `local` log driver, so server installs fail with `invalid log driver`. Wings also mounts its temporary directory into install containers, and SELinux blocks containers from reading `/tmp/pelican`. In `/etc/pelican/config.yml`, change these two values:

    ```yaml title="/etc/pelican/config.yml"
    system:
      tmp_directory: /var/lib/pelican/tmp
    docker:
      log_config:
        type: k8s-file
    ```

4. Allow containers to use the Wings data directories under SELinux, then restart Wings:

    ```sh
    sudo mkdir -p /var/lib/pelican/tmp
    sudo semanage fcontext -a -t container_file_t "/var/lib/pelican(/.*)?"
    sudo restorecon -R /var/lib/pelican
    sudo systemctl daemon-reload
    sudo systemctl restart wings
    ```

:::warning
Keep the OOM killer enabled on every server. Podman uses cgroup v2, which can't disable it, so a server with the OOM killer disabled fails to install or start with `cannot disable OOM killer with cgroupv2`.
:::
