Migrating from Pterodactyl

Upgrade a Pterodactyl install to Pelican in place, keeping users, servers, nodes and eggs, with the Panel and Wings migration scripts or Docker.

Pelican upgrades your Pterodactyl database in place: users, servers, nodes, eggs, databases, backups, schedules, subusers and API keys all carry over. Your game servers keep running and keep their files.

Back up first

The migration changes your database and can't be undone. Back up your database, /var/www/pterodactyl and /etc/pterodactyl before you start. If anything goes wrong, ask on Discord.

Requirements

  • Pterodactyl 1.11.4 or newer. Update Pterodactyl first if needed.
  • The Panel dependencies, including PHP 8.4 or newer with PHP-FPM.

Migrate the Panel

Download the script and run the checks. They change nothing and tell you exactly what to fix, like a PHP version that's too old or a missing extension.

Once every check passes, run the migration:

It installs Pelican in /var/www/pelican, copies your .env and upgrades the database. It also sets up the queue worker and cron job. Your old install stays untouched in /var/www/pterodactyl.

Last, point your webserver at /var/www/pelican/public and disable the Pterodactyl site.

Take Pterodactyl offline first, so nothing writes to the database:

Then remove the Pterodactyl schedule:run line from sudo crontab -e.

Create the compose.yml from the Docker guide and add these to its environment:

If you use host.docker.internal, MySQL and Redis must listen on the Docker network (not only 127.0.0.1), and your database user must be allowed to connect from 172.20.0.0/16.

Copy your Pterodactyl .env into the container before its first start:

The container serves the Panel on ports 80 and 443, so stop the webserver that served Pterodactyl first (for example sudo systemctl disable --now nginx).

Start it. The database is upgraded on startup, so wait for that to finish before seeding:

If the wait never ends, the upgrade failed. Check docker compose logs panel.

Migrate Wings

Run this on every node. It checks everything first, then swaps in Pelican Wings and keeps your existing config and server files.

What changes

  • Nests and locations become tags. Eggs get a tag with their old nest name and nodes get one with their old location.
  • API keys keep working, including old ptla_/ptlc_ keys. The nests and locations API endpoints are gone, see the API docs.
  • Root admins get the Root Admin role.
  • Themes and panel modifications don't carry over. Look for a plugin instead.
Migrating by hand

Use this instead of the scripts if you want to run each step yourself.

Stop Pterodactyl and back up the database.

Install Pelican. Follow the Standalone Install up to (and including) Install Composer, but don't run the web installer. Then copy your .env and upgrade the database. Make sure .env has DB_CONNECTION=mysql, or DB_CONNECTION=mariadb on MariaDB: Pterodactyl didn't need it, but without it Pelican falls back to SQLite.

HASHIDS_SALT, HASHIDS_LENGTH, APP_THEME and APP_ENVIRONMENT_ONLY are no longer used and can be removed from .env.

Finish the setup. Set permissions and configure your webserver. Then set up the queue worker and cron job, and bring the Panel up:

Wings, on every node:

Update /etc/systemd/system/wings.service to match the one in Installing Wings (the working directory is now /etc/pelican), then run sudo systemctl daemon-reload and sudo systemctl start wings.
